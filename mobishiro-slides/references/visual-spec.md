# モビシロ visual spec

## 基本方針

- スマホ縦持ちを前提にした9:16のHTMLスライド。
- 白を主役にし、装飾より余白と文字組みで見せる。
- スライド内の優先順位は、ヘッダー、タイトル、補足文、ページ番号。
- 1枚につき1メッセージ。情報を詰め込まない。

## 画面と寸法

- スマホ基準 viewport: 390 × 844 px。
- スライド比率: `aspect-ratio: 9 / 16`。
- スライド幅: `min(430px, 88vw, 42.75dvh)`。
- スライド角丸: 24 px。
- スライド内余白: 幅・高さの約9%。
- デスクトップでは360 × 640 px相当で中央表示する。

## 色

- 外側背景: `#f6f7f9`。
- スライド背景: `#ffffff`。
- 主文字: `#17191f`。
- 補助文字: `#747983`。
- 境界線: `#e6e8ec`。
- アクセント: `#2e67d1`。
- 強い影、グラデーション、テクスチャは使わない。

## タイポグラフィ

- システム日本語フォントを使用し、外部フォントへ依存しない。
- ヘッダー: 10〜12 px、太字、字間を広め、アクセント色、下罫線。
- タイトル: 28〜46 px、太字、行間約1.0、負の字間を軽く設定。
- 補足文: 13〜16 px、行間約1.75、補助文字色。
- ページ番号: 11 px、字間を広め、補助文字色。

## 文体

- 文言は淡々とした説明文にする。事実、資料上の主張、データから分かること、実施内容のいずれかを具体的に述べる。
- 広告コピーのような短句、詩的な言い回し、比喩、体言止めの連続、含みを持たせた抽象表現を使わない。
- 強調のためだけに読点や句点を挿入しない。通常の日本語として必要な句読点だけを使う。
- 読点、助詞、修飾語の途中で手動改行しない。原則としてブラウザの自然な折り返しに任せる。
- 手動の `<br>` は、意味のまとまりを保ちつつ画面幅へ収める必要がある場合だけ使う。
- タイトルも内容を説明する一文または具体的な名詞句にする。「何を示すか」「何が分かるか」が一読で判断できる表現を優先する。

悪い例:

```text
濃淡で、集中を
見つける。
```

良い例:

```text
グリッドに濃淡を付けて、値の集中を可視化します。
```

別の良い例:

```text
水曜日の18時にアクセスが集中しています。
カテゴリ別の売上を降順で比較します。
調査結果から、継続率は6か月間で23ポイント上昇したことが分かります。
```

## 構成

各 `.slide` は原則として次の構造にする。

```html
<article class="slide">
  <div>
    <p class="eyebrow">SECTION / 01</p>
    <h2>調査結果から分かることを具体的に記述します。</h2>
    <p class="lead">必要な場合だけ、根拠や条件を短く補足します。</p>
  </div>
  <p class="slide-number"></p>
</article>
```

## 操作

- 横方向のスクロールスナップで1枚ずつ移動する。
- 画面下部のドットで任意ページへ移動できる。
- キーボードの左右矢印キーでも移動できる。
- JavaScriptでスライド数、ページ番号、ドット、ARIAラベルを同期する。
- `prefers-reduced-motion` を尊重し、不要なアニメーションを使わない。

## 検証

- 390 × 844 pxで最初と最後のスライドを確認する。
- スライド実寸が9:16であることを確認する。
- 全タイトルと補足文がスライド内に収まることを確認する。
- タイトルと補足文が事実・主張・読み取れる内容を具体的に述べ、コピー調や装飾的な改行になっていないことを確認する。
- ドット選択後、選択状態と表示ページが一致することを確認する。
