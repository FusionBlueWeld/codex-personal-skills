# モビシロ・スライド

白背景、9:16、短いヘッダーと大きなタイトルを核にした、スマホ閲覧用HTMLスライドを作成する。

## ワークフロー

1. 対象案件の作業フォルダ、入力資料、希望ファイル名を確認する。未指定なら `モビシロ.html` を使う。
2. [references/visual-spec.md](references/visual-spec.md) を必ず全文読む。
3. グラフを含む場合は [references/chart-patterns.md](references/chart-patterns.md) を必ず全文読み、基本表現と選択基準を適用する。
4. `assets/mobishiro-template.html` を対象フォルダへ複製し、ユーザーの内容に合わせて編集する。既存HTMLをモビシロ化する場合は、操作仕様を保ちながら同テンプレートのデザイン変数と構造を適用する。
5. `<article class="slide">` を必要枚数だけ用意する。標準は3〜6枚とし、ユーザー指定を優先する。
6. 各スライドを「短いヘッダー」「一つの主タイトル」「必要なら短い補足文」に絞る。1枚につき1メッセージを守る。
7. 外部ライブラリや外部フォントを追加せず、CSSとJavaScriptを単一HTML内に保つ。画像はユーザーが明示した場合のみ追加する。
8. スマホ幅390×844相当で表示を検証する。可能ならブラウザ操作スキルを使い、9:16比率、横スワイプ、ドット移動、文字切れ、全スライドの表示を確認する。

## 編集規則

- スライド追加・削除時は `.slide` 要素だけを増減する。テンプレートのJavaScriptがページ番号、ARIAラベル、ナビゲーションドットを自動生成する。
- ヘッダーは英数字中心の短いラベルにする。例: `OVERVIEW / 01`、`NEXT STEP / 03`。
- タイトルは原則2行以内、補足文は3行程度までに圧縮する。
- 文言はコピー調・ポエム調にせず、事実、主張、グラフや資料から分かることを平易な説明文で記述する。
- 句読点を強調のために挿入せず、読点や助詞の直後で装飾的に改行しない。手動改行は意味のまとまりと画面幅の両方から必要な場合だけ使う。
- ユーザーのブランド色指定がない限り、アクセント色はテンプレート既定値を維持する。
- 背景装飾、グラデーション、写真、カードUI、アイコンを勝手に追加しない。
- グラフは原則1枚につき1点に絞り、数値と項目名を図形の近くへ直接表示する。
- 出力先に同名ファイルがある場合は、上書きが依頼範囲か確認し、無関係な既存ファイルを変更しない。

## 出力

- 原則: UTF-8の単一 `.html` ファイル
- 必須: `meta viewport`、9:16スライド、横スクロールスナップ、タップ可能なページドット、左右矢印キー対応
- 報告: 作成ファイルのリンク、スライド枚数、表示検証の有無を簡潔に伝える

明示的に `.pptx` が要求された場合は、プレゼンテーション用スキルを併用し、このスキルはデザイン仕様として適用する。
